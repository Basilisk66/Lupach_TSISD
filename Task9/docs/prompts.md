# Промпты и комментарии к итерациям

## Промпт 1. Проектирование и допущения

```
Я делаю учебное консольное приложение на Python Ближайшие рейсы транспорта.
Требования к приложению: сортировка рейсов по времени отправления от «сейчас»; рейс в прошлом не должен
попадать в результат; нужно явно зафиксировать допущения про часовые пояса.
Предложи структуру и список допущений, которые стоит зафиксировать.
```
**Итерация:** ИИ предложил 4 модуля и список допущений. Из списка оставлено: один пояс расписания,
ежедневное расписание, aware-datetime, граница «ровно сейчас». Лишнее БД, REST API я отбросил.

## Промпт 2. Генерация основной логики

```
Напиши на Python 3.10:
1) dataclass Trip(route, transport_type, destination, departs_at) — departs_at должен быть timezone-aware, иначе пусть выкидывает  ValueError
2) функцию nearest_departures(trips, now, limit=5, route=None) -> list[Trip]:
   - рейсы с departs_at < now исключаются; рейс ровно в now — включается;
   - добавь сортировку по времени отправления, при равенстве — по route;
   - now должен быть aware, иначе выкидывает ValueError; limit >= 1;
   - фильтр по route без учёта регистра.
Добавь docstring на русском и краткие комментарии.
```
**Итерация:** первый ответ использовал `datetime.now()` без пояса и не проверял `limit`.
Вручную пришлось добавить проверки `is_aware` и `limit >= 1`. Сортировка по `(departs_at, route)` оставил как есть.

## Промпт 3. Расписание из JSON

```
Расписание хранится в JSON: {"timezone": "Europe/Moscow", "routes": [{"route", "type", "destination",
"times": ["HH:MM", ...]}]} и действует каждый день. Напиши load_timetable(path) с валидацией времени
и expand_timetable(timetable, start_date, days=2), которая создаёт aware-datetime через zoneinfo.
Объясни, почему нужно days=2.
```
**Итерация:** ИИ сначала развернул расписание только на сегодняшний день и получается что после 23:59 результат пустой.
Объяснение про `days=2` принято, `days` вынесен в параметр с валидацией.
Проверено, что нигде не используется `pytz`-метод `localize` — в `zoneinfo` его нет.

## Промпт 4. Генерация тестов

```
Напиши unit-тесты для nearest_departures. Обязательно:
- рейс в прошлом не попадает в результат;
- рейс ровно в now попадает; рейс на минуту раньше — нет;
- сортировка при неотсортированном входе и детерминированный порядок при одинаковом времени;
- limit, фильтр по route (регистр), пустой вход, всё в прошлом;
- naive now и naive Trip -> ValueError;
- now в UTC, а рейсы в Europe/Moscow;
- функция не изменяет входной список.
Время «сейчас» задавай явно, не используй datetime.now() в тестах.
```
**Итерация:** Claude добавил лишние тесты на сортировку строк и «проверку типа возвращаемого значения» —
удалены как бессмысленные. Исправлена ошибка в тесте CLI (ожидался рейс 08:05 при «сейчас» 08:10).
Итог: 25 тестов и все зелёные.
