# Задача 20: Ближайшие рейсы транспорта

**Студент:** Лупач Д.А.

## Постановка задачи

Сортировка по времени отправления от «сейчас». Тесты: рейс в прошлом не попадает. AI-review: таймзоны (хотя бы явно зафиксировать допущение).


### Принятые допущения (в т.ч. по часовым поясам)

1. Всё расписание хранится в **одном** часовом поясе — он указан в `schedule.json`.
2. Расписание действует **каждый день** (нет выходных, праздников, сезонности).
3. «Сейчас» и время рейсов — всегда **aware-datetime**.
4. Рейс, отправляющийся **ровно в момент «сейчас»**, считается доступным (`>=`).
5. Переход на летнее/зимнее время не обрабатывается специально: в демо-поясе Europe/Moscow DST нет.

## Запуск и тесты

```bash
# 1. (по желанию) виртуальное окружение
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 2. демо: ближайшие рейсы от текущего момента
python -m transport.cli

# демо с фиксированным «сейчас», лимитом и фильтром по маршруту
python -m transport.cli --now 2026-11-09T08:10 --limit 4
python -m transport.cli --now 2026-11-09T23:55 --route 5

# 3. тесты
python -m unittest -v        # без внешних зависимостей
```

### Риски и ограничения
- **Галлюцинации API:** ИИ может «придумать» несуществующий параметр (например, `ZoneInfo(...).localize()` — это метод `pytz`, а не `zoneinfo`).
  Всё проверено запуском кода и тестов.
- **«Уверенный» неверный код:** модель выдаёт неправильный тест с тем же тоном, что и правильный. Доверять можно только прогону тестов и собственному чтению.
- **Утечка данных:** в промпты не передавались персональные данные и секреты; расписание — вымышленное.
- **Лицензии:** сгенерированный код — типовой, но возможное сходство с публичными фрагментами не исключено; код прочитан и переработан вручную.
- **Ограничения решения:** одно расписание на все дни, один часовой пояс, нет обработки DST .
